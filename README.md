## Some explanations
- Why does Little Wine Launcher exist?
  - Initially, I created a script to create `.desktop` files for the user, but in practice, the idea was limited and always required access to the user's Desktop folder.
  - I decided to make the Little Wine Launcher GTK3, so it looks decent visually on any Ubuntu flavor.
- Why does Little Wine Launcher create the `$HOME/App/Little-Wine-Launcher` folder?
  - I wanted to use a non-hidden folder for the Little Wine Launcher files.
  - Little Wine Launcher also uses the `App/Little-Wine-Launcher` pattern to automatically correct saved paths.
- Is it possible to change the location of the `App/Little-Wine-Launcher` folder?
  - It's possible to use the `LWL_HOME_DIR` environment variable to specify a path.
  - In Flatpak, the XDG base directory is used by default, but the `LWL_HOME_DIR` environment variable overrides this.
  - In the Snap version, the `$SNAP_USER_COMMON` folder is used when the home plug is disconnected.
- Regarding paths like `/run/user/1000/doc/`, which are generated by the Document Portal.
  - If this is seen in the `Settings` after selecting the folders, it's not a problem. But if it appears when selecting an executable or folder, this may prevent execution.
  - If you've selected an installer that doesn't require additional files, it might still work using the Document Portal.
  - If it's an installer that needs files located in the same folder, use the "Run in Prefix" function, selecting the folder where the installer is located; that might work.
